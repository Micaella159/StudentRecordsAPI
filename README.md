# Student Records API

A RESTful API built using Node.js and Express.js for managing student records. It allows users to retrieve, create, update, and delete student information using HTTP requests.

## 1. Project Links

- **GitHub Repository:** https://github.com/Micaella159/StudentRecordsAPI
- **Public Render Deployment:** https://studentrecordsapi-ls9y.onrender.com
- **Get All Students:** https://studentrecordsapi-ls9y.onrender.com/api/students

## 2. Technologies Used

- **Node.js** – Runs the JavaScript server.
- **Express.js** – Handles API routes and HTTP requests.
- **Postman** – Tests API endpoints.
- **Git and GitHub** – Manages and stores the project source code.
- **Render** – Hosts the API online.

## 3. Requirements

Before running the project locally, install:

- Node.js
- npm (included with Node.js)
- Git (optional, for cloning the repository)
- Postman (for testing the API)

## 4. Installation and Local Execution

Follow these steps to run the API on your computer.

**Step 1: Clone the repository**

```bash
git clone https://github.com/Micaella159/StudentRecordsAPI.git
```

**Step 2: Open the project folder**

```bash
cd StudentRecordsAPI
```

**Step 3: Install the dependencies**

```bash
npm install
```

**Step 4: Start the server**

```bash
npm start
```

The server should display a message similar to:

```text
Server is running on port 3000
```

**Step 5: Open the API**

Open the following URL in your browser:

http://localhost:3000

If the server is running, it returns a message confirming that the Student Records API is running.

## 5. Student Record Fields

Each student record contains the following fields:

| Field | Description | Example |
|---|---|---|
| `id` | Unique student ID generated by the API | `1` |
| `name` | Student's full name | `"Juan Dela Cruz"` |
| `course` | Student's course | `"BSIT"` |
| `yearLevel` | Student's year level, from 1 to 4 | `1` |

## 6. API Endpoints

The following endpoints are available:

| HTTP Method | Endpoint | Purpose |
|---|---|---|
| GET | `/` | Checks whether the API is running |
| GET | `/api/students` | Retrieves all student records |
| GET | `/api/students/:id` | Retrieves a student by ID |
| POST | `/api/students` | Creates a new student record |
| PUT | `/api/students/:id` | Updates an existing student record |
| DELETE | `/api/students/:id` | Deletes a student record |

Replace `:id` with the actual student ID. For example, `/api/students/1` retrieves the student with ID 1.

## 7. Example Request Body

To create a new student, send a **POST** request to:

`http://localhost:3000/api/students`

For the deployed API, use:

`https://studentrecordsapi-ls9y.onrender.com/api/students`

In Postman, select **Body > raw > JSON** and enter:

```json
{
  "name": "Ana Reyes",
  "course": "BSIT",
  "yearLevel": 3
}
```

A successful request returns HTTP status `201 Created` and a response containing the newly created student record.

For PUT requests, use the same JSON format and include the student ID in the URL. For example:

`PUT /api/students/1`

The API validates the required fields and accepts year levels from 1 to 4.

## 8. Testing the API Using Postman

1. Open Postman.
2. Select the HTTP method you want to test.
3. Enter the local or public API endpoint.
4. For POST and PUT requests, select **Body > raw > JSON** and enter the request body.
5. Click **Send**.
6. Check the HTTP status code and JSON response.

Expected status codes include:

- `200 OK` – Request completed successfully.
- `201 Created` – A student record was created.
- `400 Bad Request` – The request contains invalid data.
- `404 Not Found` – The requested student or route does not exist.

## 9. Known Limitations

- **Temporary storage:** Student records are stored in an in-memory JavaScript array rather than a database.
- **Data resets:** Records created or modified through the API are not permanently saved. They reset when the server restarts or the deployed service restarts.
- **No authentication:** The API does not require users to log in.
- **Limited validation:** Student year levels must be integers from 1 to 4, and name and course must be non-empty strings.

## Conclusion

The Student Records API demonstrates the basic principles of RESTful API development using Node.js and Express.js. It supports CRUD operations (Create, Read, Update, and Delete), validates request data, and returns appropriate HTTP status codes. The API can be tested locally using Postman or accessed through its public Render deployment.
